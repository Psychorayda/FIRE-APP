# 验证流程优化 / Verification Flow Optimization

> 版本: 1.0  日期: 2026-07-29  状态: 已批准
> 目的：建立自动/手动验证分类标准，减少手动验证工作量，供未来里程碑复用

---

## 1. 分类标准

### 1.1 自动验证（CLI / 测试 / 静态分析）

满足以下任一条件的验证项，应归类为**自动验证**，在 CI 或本地 CLI 中完成，不进入手动验证清单：

| 判据 | 说明 |
|------|------|
| 可通过单元/集成测试断言 | 组件渲染、数据流、状态变更、函数返回值 |
| 可通过 tsc / 构建验证 | 类型正确性、编译通过、打包成功 |
| 可通过静态代码逻辑确定 | 控制流分支、数据转换公式、配置项映射 |
| 可通过 grep / 文件存在性检查 | 文档路径对齐、文件结构完整 |

### 1.2 手动验证（GUI）

以下场景**必须**手动验证，无法被自动化替代：

| 判据 | 说明 |
|------|------|
| 真实 Electron 窗口渲染 | 窗口尺寸、标题栏、devtools 行为 |
| 视觉布局 | 间距、对齐、响应式布局、滚动行为 |
| 用户主观感受 | 动画流畅度、交互反馈时机、文案可读性 |
| 跨进程交互 | IPC 通信、文件系统持久化（需真实退出重启） |
| 数据库持久化 | 应用退出后重启，数据是否保留（需真实文件系统） |

### 1.3 分类决策流程

```
验证项 → 能否用测试断言？
         ├─ 是 → 自动验证（写测试）
         └─ 否 → 能否用 tsc/构建/grep 验证？
                  ├─ 是 → 自动验证（加 CI 步骤）
                  └─ 否 → 手动验证（写 GUI 步骤）
```

## 3. M6 手动验证精简清单

仅需手动验证以下 1 项：

### FC-6：退出后数据持久化
1. 启动应用，完成 onboarding（如未完成）
2. 进入 FIRE 计算器，创建或编辑场景
3. 点击保存
4. **完全退出**应用（关闭所有窗口）
5. 重新启动应用
6. 验证：不重新进入 onboarding，FIRE 场景数据保留

## 4. 可复用模板

未来里程碑的验证清单生成流程：

### 4.1 生成验证清单时
1. 逐项检查 spec 验收标准
2. 对每项应用 §1.3 分类决策流程
3. 标注 自动/手动 + 自动验证实现位置
4. 仅将"手动"项列入手动验证清单

### 4.2 实施完成时
1. 运行全量测试 + tsc + 构建（自动验证项默认覆盖）
2. 仅对"手动"项执行 GUI 验证
3. 如果手动项发现 bug，修复后重新验证

### 4.3 模板格式

```markdown
## [里程碑名称] 验证清单

### 自动验证（CI 覆盖）
| 编号 | 检查点 | 实现位置 |
|------|--------|---------|
| XX-1 | ... | tests/xxx.test.ts |

### 手动验证（GUI）
| 编号 | 检查点 | 步骤 |
|------|--------|------|
| XX-2 | ... | 1. ... 2. ... |
```

## 5. 持续改进

- 每次里程碑结束后，复审手动验证项是否有新增测试覆盖
- 若发现某项手动验证可被测试覆盖，立即补测试并移出手动清单
- 测试覆盖率提升是减少手动验证工作量的根本路径
