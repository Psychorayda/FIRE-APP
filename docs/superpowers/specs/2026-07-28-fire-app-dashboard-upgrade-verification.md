## §1 验证范围与前置

### 1.1 背景

Dashboard 升级自动化验证（renderer 114 测试 + 构建成功）已覆盖纯函数逻辑、组件交互、容器数据流。但以下三类风险是自动化测试盲区：

1. **真实 IPC 集成**：测试 mock 了 dataAccess，真实 sqlite + IPC 跨进程通信未验证
2. **打包版路径迁移**：本次推送包含 git reset + 重新应用到根目录结构，需确认打包版无文件缺失
3. **视觉与交互流畅性**：Tailwind 样式渲染、Recharts 图表、布局、响应速度

本验证计划以"手动 GUI 交互"组织，对 dashboard 升级 + M4 回归进行真实环境验证。

### 1.2 验证范围（5 项）

| # | 验证项 | 目的 | 对应验收标准 |
|---|--------|------|-------------|
| H-1 | 启动 + onboarding + 仪表盘空状态 | 真实打包版启动，onboarding 流程，dashboard 空状态正确显示 | D-1, D-6 |
| H-2 | 创建账户后仪表盘净资产卡 | 净资产 3 卡正确显示，金额计算正确 | D-2 |
| H-3 | 创建交易后仪表盘收支卡 + 近期交易 | 本月收支 3 卡 + 近期交易表正确显示 | D-3, D-5 |
| H-4 | 多月份后趋势图 + 视觉检查 | 趋势图显示逻辑 + 全模块视觉验证 | D-4, D-6 |
| H-5 | M4 交易页回归 | 确认路径迁移未破坏 M4 交易管理功能 | M4 回归 |

### 1.3 验证方法

| 方法 | 适用 | 执行方 |
|---|---|---|
| 真实 GUI 交互 | 全部 5 项 | 用户本地执行 |
| 选项式对话确认 | 逐项结果收集 | AI 通过 AskUserQuestion |
| 实时修复 | 发现的 bug | AI 修复 + 回归验证 |

### 1.4 修复流程

发现 → 定位根因 → 修复 → 回归验证（pnpm test + build）→ 独立 commit（消息前缀 `fix(dashboard):`）。

### 1.5 环境前置

- 从 [CI run 30365075718](https://github.com/Psychorayda/FIRE-APP/actions/runs/30365075718) 下载 `fire-app-windows` artifact
- 解压运行 exe（nsis 安装包或 portable 免安装版）
- Windows 环境，Node/electron 环境由打包版自带，无需本地 Node

### 1.6 数据准备策略

- 打包版 userData 路径为 `%APPDATA%/FIRE App/fire-app/data/fire.db`，与 dev 模式（`@fire-app/desktop`）不同
- 验证从 onboarding（空状态）开始，边验证边创建数据
- 数据准备融入验证流程，不单独前置

### 1.7 已知问题（不在本次验证范围）

- **dev 与打包版 userData 路径不一致**：`app.name` 在 dev 是 `@fire-app/desktop`（来自 package.json name），打包后是 `FIRE App`（来自 electron-builder.yml productName）。这是 Electron 标准行为，非 bug，但影响数据复用。记录为已知问题，后续里程碑可考虑统一（如显式 `app.setName` 或统一 productName）。

| # | 检查点 | 预期 |
|---|--------|------|
| a | 总资产 | ¥15,000.00（10000+5000，流动资产之和） |
| b | 总负债 | -¥200,000.00（房贷，负数显示） |
| c | 净资产 | -¥185,000.00（总资产+总负债，负数） |
| d | 净资产颜色 | 负数时文字为红色（text-red-600） |
| e | 数据加载 | 切回仪表盘时自动刷新，无需手动操作 |
